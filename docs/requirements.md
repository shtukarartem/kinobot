# Требования

## Контекст

Нужен Telegram-бот для двух пользователей, которые ведут общий список фильмов и сериалов: что посмотрели, что смотрят и что хотят посмотреть.

## Роли

### Разрешенный пользователь

Может:

- искать фильмы и сериалы;
- добавлять тайтл в список;
- смотреть общий список;
- редактировать записи;
- удалять записи;
- ставить оценку;
- оставлять заметку.

### Неразрешенный пользователь

Не может пользоваться ботом. Получает сообщение:

```text
У вас нет доступа к этому боту.
```

## Функциональные требования MVP

### Авторизация

- Бот проверяет `ctx.from.id`.
- Разрешенные id берутся из `ALLOWED_TELEGRAM_USER_IDS`.
- Проверка применяется ко всем действиям, включая callback-кнопки.

### Поиск

- Пользователь вводит `/search название` или просто пишет название.
- Бот отправляет запрос в ПоискКино API.
- Бот показывает до 5 результатов.
- Каждый результат содержит:
  - название;
  - год;
  - тип: фильм или сериал;
  - рейтинг Кинопоиска, если есть;
  - краткое описание, если есть.
- У каждого результата есть кнопка добавления.

### Добавление

- Пользователь выбирает результат поиска.
- Бот сохраняет тайтл в PostgreSQL.
- Если тайтл уже есть в списке, бот сообщает об этом и предлагает открыть существующую запись.
- По умолчанию запись добавляется со статусом `watched`.

### Просмотр списка

- `/list` показывает общий список.
- Список сортируется по дате добавления или дате просмотра, новые сверху.
- Для каждой записи показываются:
  - название;
  - год;
  - тип;
  - статус;
  - кто добавил;
  - оценка, если есть.

### Редактирование

Пользователь может изменить:

- статус;
- оценку от 1 до 10;
- заметку;
- дату просмотра;
- признак совместного просмотра.

### Удаление

- Запись можно удалить только после подтверждения.
- Для MVP удаление физическое.
- Позже можно заменить на soft delete.

## Нефункциональные требования

- Бот должен стабильно переживать перезапуск процесса.
- Данные хранятся в PostgreSQL.
- Все внешние токены хранятся только в переменных окружения.
- Ошибки внешнего API не должны падать процесс.
- Ответы бота должны быть короткими и понятными.

## Ограничения MVP

- Только один общий список.
- Без веб-интерфейса.
- Без сложных рекомендаций.
- Без многоязычного интерфейса.
- Без OAuth или регистрации пользователей.

## Будущие возможности

- Раздельные списки: просмотрено, планы, избранное.
- Фильтры по жанру, году, типу и оценке.
- Статистика по пользователям.
- Экспорт списка в CSV.
- Напоминания о продолжении сериала.
- Отдельный список "хотим посмотреть вместе".
